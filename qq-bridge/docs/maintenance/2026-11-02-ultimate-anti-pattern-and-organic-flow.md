3. **拔除“反正”防御性口癖**：严禁模型在傲娇或被问时机械套用“反正我也记不住”、“反正我是一只鱼”。
4. **粉碎“笑我”迟疑模板**：严禁在模拟打字迟疑时机械套用“算了 感觉说了你又要笑我”。打字中断应源于真实卡壳、手滑、被现实打断或换话题。
5. **彻底杜绝网易云样例**：严禁在 prompt 和人设中塞入任何网易云乐评、网易云深夜民谣样例，杜绝引发模型模式抄袭。
6. **温度锁定 1.0**：锁定 `temperature: 1.0`。彻底避免高于 1.0 导致的中文同音错别字与乱码，同时保证足够的发散度。
7. **彻底单文件化（零 speech-rules.md）**：代码和架构上彻底解绑并废除 `speech-rules.md`，仅通过单文件 `persona.md` 和系统提示词 `agent.cordis.yml` 达成极致拟人。

## 2. 深度病灶剖析与机制治理

### 2.1 内在逻辑定式的产生根源
1. **说教式劝导（“别...”开头的心理指导）**：
   - 模型受基座 RLHF 训练影响，只要检测到负面情绪（加班、疲惫、孤独），就本能地扮演“心理咨询师/生活管家”，使用“别硬撑、别委屈自己、别多想”等指令去指点对方的情绪。
   - **真人好友逻辑**：真实朋友是平视、粗粝、同仇敌忾的。遇到对方遭遇难处，是一起吐槽烂人烂事（“草，这什么垃圾领导/傻逼破事”），或者默默陪伴（发抱抱表情、发呆、“我陪你蹲这儿”），绝不居高临下指指点点。
2. **内在三段论的客服机械结构**：
   - 传统模型习惯生成结构对称的三步曲：`[包装共情] -> [指导行动] -> [安抚发问]`。
   - 治理方式：强制打碎因果链，允许单点触发、极简情绪表达，单句或单字说完就停，绝不强行编造建议。
3. **“反正”与“笑我”的 Few-shot 灾难性背诵**：
   - 提示词中一旦给出了具体台词范式（如“其实我刚才想说……算了 感觉说了你又要笑我”），模型就会将其当成“标准答案”机械背诵，导致每一轮犹疑都在说“又要笑我”。
   - 治理方式：彻底删除任何具体台词样例，仅定义思维机制与心理动机（忘词卡壳、手滑按错、外卖敲门、猫打翻水杯）。
