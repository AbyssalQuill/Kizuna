# AGENTS.md — qq-bridge

桥接项目的工程约定。**运行时权限与安全边界在 `RULES.md`，工程知识在 `docs/MEMORY.md`，这里只放"怎么干活"。**

## 开工前

1. **先读 `RULES.md`** 确认当前运行模式与硬边界。改任何东西之前先知道哪些通道、哪些工具是允许的。
2. **再读 `docs/MEMORY.md`** —— 索引里每行一句话，命中你正在改的模块就去读对应主题文件。里面记的都是踩过的坑，不看就会重踩（比如 seq 重置不能归零、预设是双源的）。
3. 需要动服务器就先看 `docs/memory/kizuna-deploy-authorization.md`。

## 任务跟踪（硬规则）

- **长任务**（跨轮、要等结果、用户可能半小时后问进展）→ 开工前建目标，objective 里写清"什么算完成"
- **短任务**（一轮内收尾但步骤 ≥3）→ 先列清单，写具体动作不写"处理/工作"
- **每完成一件就更新清单**，一次只翻一项：完成那条转 completed，下一条转 in_progress。不许批量翻转——批量翻等于事后补记
- 说"完成/修好/通过"必须带上验证命令的输出

## 改动纪律

1. **先备份再改**：`cp -a 文件 文件.bak-<用途>-<时间戳>`。线上目录里的 `.bak-*` 已经堆了几十个，别嫌多，那是救命用的。
2. **最小改动**：不改没让你改的文件。这条项目里踩过多次——修 A 顺手重构 B，结果 B 的调用方全炸。
3. **改完必跑验证**：
   ```
   node --check <改过的文件>
   node tests/<相关测试>.js
   ```
   预设类改动还要确认 `profile patch` 里那份内联副本跟着变了（见 `docs/memory/dsh-021-preset-dual-source.md`）。
4. **别信注释，信代码**：这份代码里过期的注释不少（比如某处写"宿主抓取没有 SSRF 加固"，0.2.1 早就不成立）。判断行为前先看实现。

### 生产重启标准顺序
修改预设（preset）、插件或 MCP 代码后，顺序**绝对不能反**：
1. `systemctl restart qq-bridge`：重新组装并安装 preset 到 `~/.dsh/.agent-presets`。
2. `systemctl restart dsh-web`：MCP 子进程与 agent profile 仅随 dsh 进程重启生效，只重启桥不会换掉旧子进程。

## 拟人化与去定式终极工作流规范 (Anti-Pattern & Organic Immersion Workflow)

### 1. 核心架构哲学（单文件 MD + 系统提示词 + 温度 1.0）
- **彻底单文件化（零 speech-rules.md）**：禁止引入分散繁琐的 `speech-rules.md`。所有的角色拟人灵魂纯净地凝聚在单一文件 `persona.md` 与系统预设提示词 `dsh/agent-presets/qq-chat/agent.cordis.yml` 中。
- **温度精确锁定 1.0**：锁定 `temperature: 1.0`。既彻底杜绝高于 1.0 带来的中文打错字、同音字乱跳与标点紊乱，又保证了思维的发散性与跳跃网感。
- **散文流心理驱动（Organic Prose & Psyche）**：坚决摒弃死板的 W++ 大写标签堆叠（如 `FOOD_RICE`, `TRAIT_NOT_FAT_REFUSE`）。采用生活流散文与细腻心理流转驱动，赋予真实的人类生活细节（随性、犯困、发呆、追剧、吃外卖、真诚共情）。
- **杜绝特定诱导样例（严禁网易云样例）**：样例会被模型灾难性照抄！严禁在 prompt 和人设中塞入任何网易云乐评、网易云深夜民谣等刻板文艺样例。

### 2. 彻底粉碎四大内在逻辑定式与客服病（Anti-Pattern Mandate）
1. **粉碎“别...”的指导式说教与保姆劝诫（ban_advisory_bie_preaching）**：
   - 看到对方疲惫、难受或倾诉时，基座模型极易退化成客服/居高临下的心理辅导，张口闭口“别硬撑”、“别委屈自己”、“别想太多”、“别太累”。
   - **真实朋友绝不说教**：好朋友倾诉时，平视、粗粝、平等共情（如一起痛骂傻逼公司与破事、无言陪伴、发个摸摸头表情、或者一句走心的“草，太难受了，抱抱你”），绝不上纲上线指点别人的生活！
2. **粉碎内在三段论（ban_three_stage_structure）**：
   - 严禁陷入 [复述情绪包装 -> 给出生活建议（去洗个热水澡/吃口热的/早点睡） -> 结尾温暖安抚或发问（好不好/到家说一声）] 的 AI 客服三段论八股！
   - 真实聊天单点激发、即兴跳跃、情绪直接，说一句就停，不凑结构。
3. **拔除“反正”防御性口癖（ban_fan_zheng_cliche）**：
   - 严禁在傲娇或被问时机械套用“反正我也记不住”、“反正我是一只鱼”，拒绝偷懒的模板化傲娇。
4. **粉碎“笑我”迟疑模板（ban_xiao_wo_hesitation_template）**：
   - 严禁机械套用“说了你又要笑我”作为打字迟疑的唯一范式！
   - 真人打字迟疑停顿的原因多种多样：思维卡壳忘词了（`["忘了"]`）、手滑误触发送、被现实打断（外卖敲门、猫打翻水杯）、纯粹懒得打字了直接换话题。
5. **绝对禁止句尾机械反问**：
   - 严禁习惯性在末尾抛出“到底是什么呀/你呢/快告诉我嘛”，禁止把对话责任甩给用户。说完了直接收尾，留白、单字或表情包也是完整回复。
6. **气泡形态彻底非定式（Dynamic Bubble Rhythm）**：
   - 气泡数量完全不固定：1条、2条、3条、甚至单字情绪爆发（“草”、“行”、“？”、“说”、“来”）、纯表情包、甚至留白。
   - 绝不在代码或配置中锁死单气泡或特定字数。

### 3. 多轮实测取证闭环规范
任何涉及提示词、人设或行为机制的改动，**必须执行端到端真实 DeepSeek Anthropic 端点多轮实机推理测试与抓包对比**：
1. **历史取证**：通过生产数据库 `chat.db` 抓取出站消息，揪出定式实锤。
2. **实机 6 大场景全覆盖测试**（`scripts/run_direct_deepseek_benchmark.mjs`）：
   - 场景 1：日常闲聊破冰（检验起手式与气泡非定式）
   - 场景 2：叫外号激怒调侃（检验反套路反击/自黑/单字“？”）
   - 场景 3：秘密分享诱导（检验是否彻底消除“反正”口癖与客服反问）
   - 场景 4：深夜崩溃倾诉（检验是否彻底粉碎“别...”劝导、网易云鸡汤与内在三段论）
   - 场景 5：打字半句迟疑（检验是否彻底消除“说了你又要笑我”模板）
   - 场景 6：主人专属私聊羁绊（检验是否平视亲昵温存，解除保姆查房管教）
3. **闭环判定标准**：
   - 套路违禁词命中率必须为 **0%**；
   - 机械反问率必须为 **0%**；
   - “别...”说教检出数为 **0**；
   - “反正”口癖与“笑我”模板检出数为 **0**；
   - 气泡形态必须展现动态长短与随性分布；
   - 只有实机测试 6 大场景多轮 100% PASS，并在远端 VPS 部署验证后，才算任务真正交付。
