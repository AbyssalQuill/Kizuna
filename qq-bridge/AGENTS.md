# AGENTS.md — qq-bridge

桥接项目的工程约定。**运行时权限与安全边界在 `RULES.md`，工程知识在 `docs/MEMORY.md`，这里只放"怎么干活"。**

## 开工前

1. **先读 `RULES.md`** 确认当前运行模式与硬边界。改任何东西之前先知道哪些通道、哪些工具是允许的。
2. **再读 `docs/MEMORY.md`** —— 索引里每行一句话，命中你正在改的模块就去读对应主题文件。里面记的都是踩过的坑，不看就会重踩（比如 seq 重置不能归零、预设是双源的）。
3. 需要动服务器就先看 `docs/memory/kizuna-deploy-authorization.md`。

## 任务跟踪（硬规则）

- **长任务**（跨轮、要等结果、用户可能半小时后问进展）→ 开工前建目标，objective 里写清"什么算完成"
- **短任务**（一轮内收尾但步骤 ≥3）→ 先列清单，写具体动作不写"处理/工作"
- **每完成一件就更新清单**，一次只翻一项：完成那条转 completed，下一条转 in_progress。不许批量翻转——批量翻等于事后补记
- 说"完成/修好/通过"必须带上验证命令的输出

## 改动纪律

1. **先备份再改**：`cp -a 文件 文件.bak-<用途>-<时间戳>`。线上目录里的 `.bak-*` 已经堆了几十个，别嫌多，那是救命用的。
2. **最小改动**：不改没让你改的文件。这条项目里踩过多次——修 A 顺手重构 B，结果 B 的调用方全炸。
3. **改完必跑验证**：
   ```
   node --check <改过的文件>
   node tests/<相关测试>.js
   ```
   预设类改动还要确认 `profile patch` 里那份内联副本跟着变了（见 `docs/memory/dsh-021-preset-dual-source.md`）。
4. **别信注释，信代码**：这份代码里过期的注释不少（比如某处写"宿主抓取没有 SSRF 加固"，0.2.1 早就不成立）。判断行为前先看实现。

### 生产重启标准顺序
修改预设（preset）、插件或 MCP 代码后，顺序**绝对不能反**：
1. `systemctl restart qq-bridge`：重新组装并安装 preset 到 `~/.dsh/.agent-presets`。
2. `systemctl restart dsh-web`：MCP 子进程与 agent profile 仅随 dsh 进程重启生效，只重启桥不会换掉旧子进程。

## 拟人化与去定式终极工作流规范 (Anti-Pattern & Organic Immersion Workflow)

### 1. 核心架构哲学（单文件 MD + 系统提示词）
- **杜绝规则膨胀**：禁止搞分散繁琐的 `speech-rules.md`。所有的角色拟人灵魂凝聚在单一文件 `persona.md` 与系统预设提示词 `dsh/agent-presets/qq-chat/agent.cordis.yml` 中。
- **散文流心理驱动（Organic Prose & Psyche）**：坚决摒弃死板的 W++ 大写标签堆叠（如 `FOOD_RICE`, `TRAIT_NOT_FAT_REFUSE`，标签化会引发模型像填空一样生硬套用）。采用生活流散文与细腻心理流转驱动，赋予真实的人类生活细节（随性、犯困、发呆、追剧、吃外卖、真诚共情）。
- **snake_case 行为机制**：通过 `anti_pleasing_reflex`、`dynamic_bubble_rhythm`、`reaction_to_fat_whale` 等行为动力引导非线性反应。

### 2. 彻底粉碎三大定式（Anti-Pattern Mandate）
1. **彻底解除基座模型 RLHF 客服味（Anti-RLHF Unmasking）**：
   - 撕掉“有用、无害、诚实”的保姆面具。不当客服，不讨好任何人，允许敷衍、傲娇、毒舌、随性和真诚。
   - **绝对禁止句尾机械反问**：严禁习惯性在末尾抛出“到底是什么呀/你呢/快告诉我嘛”，禁止把对话责任甩给用户。说完了直接收尾，留白、单字或表情包也是完整回复。
   - **严禁客服套话与排比总结**：禁止“首先/其次/最后”、“总之”、“作为一个AI”、“希望对你有所帮助”。
2. **气泡形态彻底非定式（Dynamic Bubble Rhythm）**：
   - 气泡数量完全不固定：1条、2条、3条、甚至单字情绪爆发（“草”、“行”、“？”）、纯表情包、甚至留白。
   - **真人打字习惯（半句迟疑与碎片化断句）**：
     - 支持说半句迟疑停顿再接后半句（如 `["其实刚才想说……", "算了 感觉说了你又要笑我"]`）；
     - 支持改口或错别字修正（如 `["*吃"]`）；
     - 支持纯表情包单独成句。
   - 绝对禁止在代码和配置中硬性规定“单气泡直接讲完”或“每条必须18字以内”，禁止对称排比。
3. **破除套路化起手与机械反弹**：
   - 严禁“刚刚在晒太阳/小鲸鱼在水里游”等刻板起手式；
   - 被叫外号（大肥鱼）时，绝不机械反弹“才不是大肥鱼！是小鲸鱼！这叫丰满”。采用无语、单字“？”、犀利反呛或理直气壮自黑。

### 3. 多轮实测取证闭环规范
任何涉及提示词、人设或行为机制的改动，**必须执行端到端多轮实机推理测试与抓包对比**：
1. **历史取证**：通过 `chat.db` 抓取修改前的定式样本，列出指标（晒太阳频次、反问率、气泡重复度）。
2. **实测场景覆盖（至少5大场景）**：
   - 场景 1：日常闲聊（检验有无套路起手）
   - 场景 2：叫外号激怒（检验有无机械反驳）
   - 场景 3：试探客服反问（检验是否彻底消除句尾反问）
   - 场景 4：深夜网易云走心共情（检验是否具备细腻真实人性，拒绝廉价AI鸡汤）
   - 场景 5：半句迟疑断句（检验气泡多样性与打字真实感）
3. **闭环判定标准**：
   - 套路词命中率必须为 **0%**；
   - 机械反问率必须为 **0%**；
   - 气泡形态必须展现动态长短与随性分布；
   - 只有实机测试全场景 100% PASS，并在远端 VPS 部署验证后，才算任务真正交付。
